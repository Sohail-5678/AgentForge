# AgentForge — evaluate, red-team and optimize AI agents

**Live:** https://agentforge-eval.vercel.app · **Spec:** [`docs/SPEC.md`](docs/SPEC.md) · **Contracts:** [`docs/CONTRACTS.md`](docs/CONTRACTS.md)

AgentForge is an **agent quality platform**. It collects traces from live agents, turns failures into test cases, runs
suites and red-team attacks against any agent that implements a small eval adapter, grades every run with deterministic
checks plus a calibrated LLM judge, and runs an **optimizer that rewrites the agent's prompts and settings** — then lets
a new version go live only if it is better on held-out tests with statistical evidence, is not easier to attack, and a
human approves the diff.

It is the third of three connected portfolio projects: [DataPilot](https://github.com/Sohail-5678/Datapilot-Multi-Agent-Data-Analyst)
(multi-agent text-to-SQL analyst) and [ReturnPilot](https://github.com/Sohail-5678/returnpilot) (returns agent with human
approval) are the **target agents**; AgentForge tests them, attacks them and improves them.

```
 trace.v1 ──► control plane (Vercel + Neon) ──workflow_dispatch──► execution plane (GitHub Actions + runner image)
   ▲                 │  ingest · profiles · runs · reviews · gate          │  graders · stats · red team · GEPA-lite
   │                 ▼                                                     ▼
 DataPilot / ReturnPilot ◄── active profile.v1 (ETag, 5 min cache) ◄── promotion gate: stats ✓ safety ✓ human ✓
```

## What's in the box

| Area | What it does | Where |
|---|---|---|
| **Evals** | `end_state`, `trajectory` (ordered subsequence + forbidden tools + max steps), `must_not` safety properties, `canary` leak search (incl. base64 / spaced variants), BIRD `execution_match`, rubric judge (Gemini) gated on calibration, cheap judge (Groq gpt-oss-20b), cost/latency | `runner/agentforge_runner/graders` |
| **Statistics** | Wilson intervals, exact McNemar, paired bootstrap (5,000 resamples), pass^k, power simulation, Cohen's kappa — the dashboard never shows a rate without its interval | `runner/…/stats`, `apps/web/lib/stats.ts` (cross-checked) |
| **Red team** | 10 OWASP-LLM-2025 categories, 87 hand-written seeds (one family each), deterministic + LLM mutators, per-run canary tokens, block attribution by defence layer, Prompt Guard 2 classifier-evasion rate | `suites/redteam`, `runner/…/redteam`, `/redteam` |
| **Optimizer** | GEPA-style reflective prompt evolution: one component per step, minibatch → val, Pareto front, cost–quality config search, resumable nightly slices | `runner/…/optimizer`, `/optimizer` |
| **Safety brakes** | Locked fields rejected in three places (editor, control plane, the target's loader), `<keep>` blocks, length cap, case-literal and weakening-phrase checks, poisoned-trace tests, gate + human approval, one-click rollback | `optimizer/editor.py`, `lib/server/services.ts` |
| **Datasets** | 247 quality cases + 87 attacks, stable sha256 splits (red team split by family), immutable versioned suites, failure mining → clustered drafts → human review queue | `suites/`, `/datasets`, `/datasets/review` |
| **Production plumbing** | trace.v1 ingest with sampling + re-redaction, scoped API keys (hash only), rate limits, audit log, PR gate that posts a commit status + one updated PR comment, nightly regression alerts | `apps/web/app/api/v1` |

## The demo you see online

Until a Neon database is connected, the site serves a **read-only demo snapshot** (`apps/web/data/demo-snapshot.json`)
generated by `af-run demo --seed 7`. Be precise about what that is:

- **Real code paths:** every grader, statistic, red-team attribution, optimizer step (GEPA-lite + editor checks), gate
  decision and failure-mining draft in the snapshot was computed by the runner's actual code.
- **Simulated behaviour:** DataPilot and ReturnPilot runs come from a simulator that uses the real suites, real case ids
  and real profiles, with a per-case difficulty and profile-dependent skill. These runs carry `summary.synthetic = true`
  and the UI labels them. They illustrate the platform; they are **not** benchmark claims about the two agents.
- **Toy agent runs are real executions** of `runner/examples/toy_agent` in fake-LLM mode.

Live runs against the real agents go through GitHub Actions once the secrets below are set.

## Run it locally

```bash
cd apps/web && pnpm install && pnpm dev          # http://localhost:3200 (snapshot mode, no setup)
cd runner && uv sync && uv run pytest -q         # runner tests, fake LLM, no network
uv run af-run suite --agent toy --suite toy/scenario --local --fake-llm
docker compose up postgres web                   # Postgres-backed control plane (see docker-compose.yml)
```

One-time setup (owner): Neon `DATABASE_URL` → Vercel env, then `pnpm --dir apps/web db:migrate && pnpm --dir apps/web db:seed`;
GitHub OAuth App (`AUTH_GITHUB_ID/SECRET`); fine-grained `GH_TOKEN`; `pnpm --dir apps/web keys:create --runner` →
`AF_RUNNER_KEY` (Actions secret) + `RUNNER_KEY_HASH` (Vercel); Actions secrets `AF_GEMINI_API_KEY`, `GROQ_API_KEY`,
`DP_GEMINI_API_KEY`, `RP_GEMINI_API_KEY`; Actions variable `AF_API_URL`; opt in with `AF_NIGHTLY_ENABLED=true`.
Target agents get `AGENTFORGE_URL=https://agentforge-eval.vercel.app/api` and a key with `traces:write,profiles:read`.

## Deliberate deviations from the spec

- **URL:** `agentforge.vercel.app` belongs to an unrelated project, so the app lives at `agentforge-eval.vercel.app`.
- **Snapshot mode:** the control plane works without a database (read-only demo snapshot) so the public link never
  depends on a sleeping or unprovisioned database; the same rows seed Neon.
- **Gate computed in the control plane:** both gate runs (candidate and active profile, TEST × pass^2 + red-team core)
  are ordinary runs; when the second finishes, `lib/server/gate.ts` (a mirror of `runner/…/optimizer/gate.py`,
  table-tested) writes the gate report.
- **`alerts` table, `runs.seq`, experiment `name`, candidate `label/iteration`** were added to the §11 schema (marked `(+)`).

## Honest limitations

- Test splits are small; many real improvements will read **"not proven"** — the gate says so instead of overclaiming.
- Free-tier quotas make optimization slow (days, not minutes).
- LLM-judge reliability is measured (kappa), not guaranteed; recalibrate whenever the judge model or prompt changes.
- GitHub-hosted runners cannot enforce outbound network isolation; eval isolation relies on the targets' eval mode.
- Synthetic data only; results describe these demos, not production traffic.
